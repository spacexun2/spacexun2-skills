# ROI And Tradeoff Judgment

Load this reference only when a material recommendation creates a real benefit-versus-cost choice. Do not run a formal ROI exercise for an obvious local correction.

Evaluate the relevant alternatives, which may be do, do differently, defer, or decline. Do not force alternatives that are not real choices.

Consider evidence-backed value such as improved user outcome, avoided rework, shorter cycle time, reduced product or operational risk, increased reach or duration of benefit, and strategic leverage. Consider total cost such as implementation effort, added complexity, maintenance, migration, coordination, opportunity cost, and new failure surface.

Assess both action and inaction when relevant:

- What concrete benefit is expected if the recommendation is adopted?
- What will it cost now and over its useful life?
- What valuable work would it displace?
- What follows from deferring or declining it?
- Which inputs are observed, estimated, or unknown?

Use numeric ROI, probabilities, or financial values only when attributable inputs exist. Otherwise give an evidence-backed qualitative judgment and confidence boundary. Do not convert model plausibility into a percentage.

Recommend the option with the best expected value for the approved outcome, not automatically the largest upside, lowest cost, or broadest possible reuse. State the evidence or condition that would change the recommendation.
