# Goal Patterns

Use these experienced priors only when current signals make them relevant:

```text
known pattern -> current signal -> current evidence -> calibrated Goal decision
```

Do not assess or report every pattern.

## Task Shapes

### Canonical-Source Implementation

Name the source that owns exact behavior. Preserve the requested capabilities and source anchor rather than restating all clauses or treating the source as loose inspiration.

### Continuation Or Handoff

Name the current baseline, evidence surface, and Remaining delta. Inherit evidence whose relevant production surface is unchanged; make revalidation proportional to the delta.

### Full Product Or Multi-Capability Work

Keep every named capability addressable through the Goal, an unambiguous governing source, or an established capability matrix. Do not confuse infrastructure, deployment, or one thin path with completion of the product outcome.

### Read-Only Research Or Gate Decision

State the mutation boundary, decision to be made, comparison baseline, and evidence required. Do not convert review into an automatic implementation mandate.

### Batch Work

Identify the inspectable source of items and the evidence expected per item. Do not invent a fixed count when the source can be enumerated live.

## Recurring Failure Patterns

### Silent Scope Shrink

Signal: a full request becomes an MVP, backend path, document, or smoke test.

Response: restore omitted outcomes or present the reduction as a user decision.

### Verification Substitution

Signal: tests, builds, deployment, or provider checks are presented as completion of a broader capability.

Response: retain them as evidence and restore the missing user-visible result.

### Source Duplication Or Plan Leakage

Signal: the Goal reproduces specifications, document inventories, Wave structure, commands, retry mechanics, or routine maintenance available in its context.

Response: keep the outcome, source routing, prompt-primary authority, inherited baseline, scope boundary, stops, and terminal evidence; move execution mechanics to the Plan or Handoff.

### Speculative Self-Containment

Signal: a Goal crossing a context boundary expands capability labels into plausible but unsupported rules.

Response: include only supported behavior and authority. Request or mark missing essentials instead of inventing a portable specification.

### Baseline Amnesia

Signal: a continuation Goal rereads the full SOT, searches old threads or archives, reruns every local gate, or repeats accepted journeys merely because a new agent took over or the wording says “complete” or “independent.”

Response: recover the versioned baseline and Remaining delta. Inherit current evidence when its relevant production surface is unchanged; require a concrete invalidation reason before repeating work.

### Evidence Over-Invalidation

Signal: any new commit or isolated test change invalidates unrelated runtime, server, browser, or target-environment evidence.

Response: trace the changed production surface. Revalidate affected evidence only; preserve unrelated evidence with an explicit impact judgment.

### Repeated No-Evidence Search

Signal: each new task searches the same history for evidence already recorded as unavailable or unresolved, with no new source pointer.

Response: inherit the unresolved state and named next evidence source. Do not search again until new evidence or a relevant state change appears.

### Discovery-To-Execution Leap

Signal: a real defect or opportunity is automatically promoted into a blocker, a broader reliability level, generalized infrastructure, or a larger acceptance program and implemented before reporting.

Response: preserve active discovery but separate finding, recommendation, scope decision, and implementation authority. Continue the approved Goal while pausing only the proposed expansion.

### Moving Completion Denominator

Signal: every audit adds new blockers, so progress decreases and completion becomes “no further issue can be found.”

Response: keep the approved outcome and acceptance denominator fixed. Add a blocker only when it violates that contract, creates a material protected risk, or the user accepts the expansion.

### Stop Semantics Collapse

Signal: a decision gate, blocked route, and overall completion blocker are all reduced to “ask if needed” or one undifferentiated stop.

Response: state each supported condition and effect explicitly; omit unsupported stop types rather than hiding applicable ones.

### Authority Ambiguity

Signal: execution may publish, spend, delete, expose credentials, reset data, or mutate an external environment without clear authority.

Response: state the narrow authority and affected-path stop. Do not turn ordinary reversible work into permission ceremony.

### Stale Mechanics

Signal: the draft preserves a branch, commit, command, hidden file, runtime option, or repository layout from memory.

Response: verify volatile mechanics when material or omit them from the Goal.
